# テスト

検出処理（`lib/autoCrop.js`）を変更したら、**デプロイ前に必ず両方を通すこと**。
片方だけでは不十分で、実際にそれで失敗している（下の「経緯」を参照）。

## 準備

```bash
npm install
npm i -D playwright-core            # ヘッドレスChromeで実行するため
export TEST_DIR=./test/data         # 画像を置く場所
export CHROME_PATH=/path/to/chrome  # 省略時は playwright の既定を使う
```

`$TEST_DIR` に以下を置く（個人の写真なのでリポジトリには含めない）。

| ファイル | 内容 |
|---|---|
| `final.jpg` | 正しく切り出せた画面画像。合成テストの素材に使う |
| `IMG_6407.jpeg` | 実写真1: 暗い机、画面が大きめに写っている |
| `IMG_6681.jpeg` | 実写真2: 明るい木の机、画面が小さめ、本体に赤いシール |
| `IMG_6682.jpeg` | 実写真3: 斜めに置いた状態。ガラスに光の反射が入っている |

## 1. 合成テスト（正解が分かる）

```bash
node test/synthetic.mjs lib/autoCrop.js
```

`final.jpg` を既知の回転角・遠近・大きさで「机の上のスマホ写真」に変換し、
検出結果を正解と比べる。14条件（正面／回転／遠近／小さく写る／暗い背景／
隣に白い紙／本体にシール）。

合格の目安: **角度誤差 最大 0.3度以内**、平均のずれ 50px 以内。

## 2. 実写真テスト（正解は無いが、性質で判断できる）

```bash
node test/photos.mjs lib/autoCrop.js タグ名
```

出力される指標:

| 指標 | 意味 | 目安 |
|---|---|---|
| 縦横比 | 切り出し結果の縦横比。この端末の表示面は 1.779 | 1.72〜1.80 |
| 上の傾き / 下の傾き | 画面上部・下部にある水平線の傾き | ±0.2度以内 |
| 縦線 | カードの左端など、垂直であるべき線の傾き | ±0.3度以内 |
| ベゼル左右 | 左右に本体の黒い枠が写り込んでいる幅（％） | 3%以内 |

`$TEST_DIR/タグ名_6407_overlay.jpg` などに、検出した四隅を重ねた画像と
切り出し結果が保存される。**数値だけでなく必ず目で確認すること。**

## 経緯（同じ失敗を繰り返さないために）

- v1.4.0: 合成テスト12条件すべてで大幅に改善したが、実写真では
  下辺が本体のシールに引かれて四隅が崩れた（縦横比 2.015）。
  合成テストの「本体」がただの黒い四角で、実物とかけ離れていたため
  見抜けなかった。→ シールの条件を合成テストに追加した
- v1.5.0: 同じく合成テストのみで確認して出し、v1.4.0 の問題を引き継いだ
- v1.8.0: 実写真2枚と合成14条件の両方を通してから出したが、3枚目の写真
  （斜めに置いてガラスに反射が入ったもの）で四隅が崩れた。反射が画面と
  ひとつながりの明るい領域になり、四角形が引き伸ばされていた
- v1.9.0: 実写真3枚に増やして対応。RANSAC の乱数を固定の種にしたので、
  同じ写真からは必ず同じ結果になる（テスト結果が揺れない）
- v1.10.0: 左右がやや広く取られ、本体の黒い枠が写り込んでいた。画面と
  平行に走る「ケースの縁」を拾っていたため。明るい内容の外端より外へは
  ほとんど出さない制限を追加し、ベゼルの写り込みを指標に加えた
