# 画面写真の自動切り出し

スマホの画面を撮影した写真から、**画面部分だけを自動で検出**して、
台形補正（傾き補正）＋正立回転した画像を書き出すWebアプリです。

- 処理はすべてブラウザ内で完結し、画像はサーバーに送信されません
- 外部ライブラリ不要（Canvas API のみ）／APIキー不要
- 複数枚まとめて処理できます
- 自動検出が外れた場合は、四隅をドラッグして手動調整できます

## 使い方

1. 「写真を選択（複数可）」をタップして、スマホ画面を撮った写真を選ぶ
2. 自動で切り出された結果が表示される
3. 「保存」で1枚ずつ、または上の「◯枚をまとめて保存」で全部を保存

### iPhoneで写真アプリに保存する

保存を押すと**共有シート**が開くので、**「画像を保存」**を選んでください。
写真アプリ（カメラロール）に入ります。複数枚もまとめて保存できます。

`<a download>` でのダウンロードだと iPhone では「ファイル」アプリに入って
しまい写真アプリには入らないため、共有シート（Web Share API）を使っています。
共有シートに対応していないブラウザでは、自動的に順次ダウンロードになります。

うまく検出できなかったときは、

- **四隅を調整** … 青い点をドラッグして画面の四隅に合わせる
- **↺ 左に回転 / ↻ 右に回転** … 向きが90°ずれたとき
- **自動検出をやり直す** … 手動調整を元に戻す

### 「写真を選択」をタップしても何も起きないとき

**Safari で開いてください。** Chrome for iOS で開かない事例があるが、同じ版が
Safari では正常に動く。原因は特定できていない。

設定 → アプリ → Chrome → 写真 を見ても直せない。Chrome は写真の「追加のみ」の
許可しか要求しないため、読み取りを許可する選択肢がそもそも出てこない
（実機で確認済み）。写真を選ばせるときは許可の要らないシステムの写真ピッカーが
使われるので、この設定は原因ではないと思われる。

### 撮影のコツ

画面が写真の端に接しないよう、少し余白をとって撮ると検出が安定します。

## 仕組み

`lib/autoCrop.js` に処理がまとまっています。

1. 解析用に長辺640pxへ縮小し、輝度画像に変換
2. 大津の二値化で明るい領域（＝発光している画面）を抽出
3. モルフォロジー・クロージングで隙間を埋める
   （素の二値化では、画面がバナーやカードごとにバラバラの領域に分かれてしまうため）
4. 連結成分を `面積 × 四角形へのフィット具合 × 明るさ` でスコアリングし、
   画像の端に接する成分（机や背景）は減点して、画面の領域を選ぶ。
   このとき、明るい色のケースの縁（細くて長い領域）は画面ではないので外す。
   また、本体に貼ったシールのように画面の外にある小さな明るい部分は、
   四角形をゆがめるので、外したほうが画面らしくなる場合に取り除く
5. 凸包から面積最大の四角形を求める
6. **四隅を画面の縁に合わせて精密化する。**
   角丸のスマホでは、輪郭から取った四隅は角が削れているため、そのまま結ぶと
   辺が実際の縁より傾いてしまう。そこで各辺について、外側を探索して
   エッジ（輝度の変化）が最も強い位置を集め、直線をあてはめて、その交点を四隅とする。
   縁が暗くて見えない辺（画面下部の黒い余白など）は元の値を使う
7. 射影変換（バイリニア補間）で元解像度から切り出し
8. 縦長になるよう回転し、上下15%の明るさを比べて上下の向きも推定

なお、写真上では画面下部の黒い余白と本体の黒が判別できないため、
下端は「最も下にある明るい要素」までになります。必要なら四隅のドラッグで広げてください。

## ローカルでの開発

```bash
npm install
npm run dev
```

ブラウザで http://localhost:3000 を開く

## Vercelへのデプロイ

1. [Vercel](https://vercel.com) にGitHubアカウントでログイン
2. 「Add New Project」からこのリポジトリを選択
3. 設定は変更不要（環境変数も不要）のまま「Deploy」

デプロイ後のURLをスマホのSafariで開き、共有ボタン →「ホーム画面に追加」で
アプリのように使えます。
